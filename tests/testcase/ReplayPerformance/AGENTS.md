# Real Replay performance fixture (2026)

- `run_profile.py --display :1 --configuration Release --frames 1800` uses a real hardware X11 display, copies assets/configuration/Replay into a temporary data root, builds the actual production entry, and retains raw CSV/logs/metadata. Compare Debug only over the same Replay interval, backend and actual framebuffer. No implicit Xvfb/llvmpipe fallback; inspect `glxinfo.txt` and `ready.json`.
- The exact source sample is `game/Replay/thSSS_25.rpy`. Start playback through production Replay menu processing, restoring every initial `MyPlaneInfo` field, machine, rank and stage. Do not create a generic St1 simulation. Protect original Replay/Score/Setting with hash/mtime snapshots.
- Timing uses in-memory rows and buffered CSV output at completion or caught failure; never add full entity reflection/JSON tracing per frame to a performance baseline. `production_callback_ticks` comes directly from before/after the real callback and includes production pacing. Callback-external time is not an isolated GPU/swap measurement.
- Optional `THSSS.Diagnostics.ReplayPhaseCounters` fields exist only in an explicitly instrumented temporary assembly copy. Their insertion must preserve branch/switch/exception boundaries and pass direct-call/direct-return control-flow tests. Keep input DLL/native SHA256+mtime snapshots independent of source snapshots, before copying/rewriting and after execution. Never overwrite production assemblies.
- `BackgroundReplayDiagnostic=true` is an explicit marker in such a temporary copy whose focus-deactivation callback is disabled for background profiling. Only this marked copy can tolerate focus loss; normal fixture still rejects focus loss and all copies reject PauseMenu. Disclose this measurement policy override, do not call it production focus/parity validation.
- A recorded single stage may naturally request the next stage before reading the terminal 4080 word. Complete only at the recorded final key offset, matching all final player fields and an actual pending stage transition; report `recordedStageCompleted` separately from `endMarkerConsumed`. Do not infer update count merely from bytes because replay control words exist.
- Use p50/p95/p99/max and >20/>33ms counts alongside the nominal16.67ms budget. Separate CPU update, draw submission, final flush, pacing and external callback time. GPU execution is unmeasured without asynchronous GPU timestamps; CPU submission costs cannot exclude GPU stalls.
- Compare uninstrumented CSV, phase-only and phase+CPU/GC sampling on the same interval/framebuffer. Sampling overhead and environment variation must be stated. Filter EventPipe to the game main thread and distinguish GC suspensions from sampler-induced suspensions. Inclusive stack percentages overlap; native instruction samples can skid.
- Performance diagnosis does not authorize production gameplay/rendering changes or assert stable60FPS. Keep raw failures, disclose changed diagnostic policy, and preserve original player data.
- Replay timing data is aligned by consumed key offsets. A render/update callback can consume zero words (live minus-speed control or other early return); do not compare equal callback counts as equal simulated frames. Temporary profiling configuration disables DirectInput; a marked isolated diagnostic copy may additionally neutralize Form key callbacks so desktop typing cannot change replay speed. Preserve this policy in metadata rather than claiming ordinary input behavior was tested.
- `THSSS_PROFILE_STATE_HASH=1` enables optional typed gameplay/entity/RNG digest rows keyed by Replay position for correctness comparisons. These runs include additional hashing/allocation work and are not the timing-only baseline. They cover documented core fields, not arbitrary object graphs; keep independent numeric/edge differential gates.
- `OwnershipChecks/` builds a separate diagnostic-copy instrumenter. With its helper copied alongside the diagnostic game, `THSSS_PROFILE_OWNERSHIP=1` preloads it, arms the registered StageData at Ready on the real main thread, and saves the checked report at Finish. This is a correctness-only run, never an FPS measurement. The manifest classifies readonly field-address sites; reflection/native/unsafe writes and external plugins are outside coverage. Loading/suspended or unrelated stages are explicitly excluded rather than called main-thread-owned.
