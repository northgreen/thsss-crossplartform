# Math build-mode verification (2026)

- Independent SDK8 auditor/runtime probe; no game ProjectReference. `python3 tests/testcase/MathModeCompatibility/run.py verify --game /absolute/THSSS.dll --mode auto --backend x87` audits actual compiled mode, SHA-bound sidecar, types/IL and cold runtime behavior. Use `--mode software` for the compile-locked backend and `--mode off` for ordinary .NET.
- Fody emits `GameplayMath.manifest.json` beside its intermediate assembly, not necessarily into output or publish directories. For enabled-mode audits set `THSSS_TEST_WEAVE_MANIFEST` to that build's real intermediate manifest. The auditor still requires rewritten shadow getters and all numeric-block helper calls in the inspected DLL; do not add a fake output manifest just to satisfy a path assumption. Off outputs must not retain a manifest or native/Fody files/dependencies.
- Off runtime probes execute with the native library removed and compare RNG, ranValue, int.MinValue behavior, distance and translated motion against normal .NET reference expressions. Old CLR golden outputs are not the expected result in off mode. Auto/software must separately retain the existing gameplay golden gates.
- Mode switching tests use the same output/intermediate location, a matching restore per mode, and inspect actual IL/files rather than just build exit status. A stale auto/software restore graph reused with off must fail clearly; do not rewrite deps.json or weaken the no-Fody check.
- Run `dotnet tests/testcase/MathModeCompatibility/bin/Release/net8.0/MathModeCompatibility.dll --self-test` after building the probe to verify deliberately contaminated IL is rejected. Packaging validation lives in `../MathModePackaging/` and the Windows frozen-byte checkout regression in `../GameplayMath/check_vendor_checkout.py`.
